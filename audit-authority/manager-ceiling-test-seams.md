# Permanent manager ceiling: regression and fixture plan

This addendum follows the parent's updated policy: Captain and Coordinator MCP always deny privileged effects; allowed operations are audited reads, manager communication and contained task actions. Host work is dispatched through authenticated human UI/API routes only. No history/source/human-pick exception and no trusted-manager test mode. Source references below are to reviewed public PR #18 head `ed152eaf5271ba84782003afe753a94ea1f4e24c`; recommendations are not claims that the policy is implemented there.

## Fixture structure without a bypass

Use one ordinary `buildMcpServer(deps, caller)` client helper, with real SDK `InMemoryTransport.createLinkedPair()` and both production manager caller types. Retain the existing helper shape in `test/hooks-mcp.test.ts:29-54` or `test/automation-status-only-mcp.test.ts:17-32`. Do not add caller fields such as `trusted`, `human`, `allowPrivileged` or `unsafeForTests`. Do not mock the policy or use an alternate unrestricted MCP builder. Server/service APIs used by fixture setup are not manager capabilities: setup runs in the test process and is never reachable through its MCP client.

Separate three layers:

1. **Production policy over real MCP.** Construct a temp Store and stopped managers. Seed projects/tasks/identities/hooks/schedules through direct Store/TaskManager/HookEngine/Scheduler methods. Connect regular MCP clients. Exercise allowed and refused calls with schema-valid arguments. Use synthetic fake managers/providers for optional dependencies; include these dependencies when testing denial of their tools, so absence of a service cannot accidentally prove authorization. Check no privileged callback ran, rather than accepting its thrown sentinel as a security refusal.
2. **Service behavior and human routes.** Move displaced setup/automation/machine/settings success assertions to their existing direct-service or human-route suites. Keep validation, rendering, deduplication, privacy, error redaction and state-transition assertions at the layer that remains authorized. Existing service methods require no new policy-disable switch. Do not add new HTTP-listening fixtures to the fast offline authority suite; human route integration remains in its separate existing tests.
3. **Real delivery/turn integration with fake execution.** Feed actual `TaskManager.apply` worker events and manager turn methods. Stub scheduling, publishing and CLI execution before creating any task. The scripted fake execution attempts actual in-memory MCP calls; it must not merely record a predicted policy result. Assert the permanent policy also applies when a manager sees mixed human/worker content, previous-session payloads, resumed turns and manager relays. No real CLI or provider command is necessary.

`test/task-containment.test.ts:15-29` shows real TaskManager dispatch with scheduling/publication disabled; `test/hooks-engine.test.ts:18-35` shows stopped TaskManager + real HookEngine + recording manager callbacks. Stopping timers alone does not prove that a public method cannot call a provider: install throwing/recording fake provider effects as well. If reusing `createBoxYard`, never start it and do not use real machine/identity/connector services that probe the host. Prefer a real isolated Store and explicitly supplied fakes for optional effects. Cleanup order: wait for fake turns to settle, close client/server transports, stop managers, then close the database. Restore spies in `afterEach`.

Define a small purpose-built snapshot of security-relevant effects: task rows/queued inputs/messages/runner-ceiling keys, hook/schedule records, project runner/identity/settings, and effect spies. Avoid brittle assertions against the entire database: an attributed refusal/report may legitimately be appended. After a denied attempt require no new executable input, task, run, runner/ceiling change, queue edit/claim, target state mutation or privileged effect. For batch denial also check no copied attachment/upload and no first-row success. Replaying the call must not change those results.

## Message, automation and persistence integration

The permanent manager ceiling removes the need to trust or classify manager conversation history for privileged authorization. It does not replace direct task-message or automation enforcement. Keep these tests independent:

- **Worker dispatch:** all three task CLIs through `TaskManager.apply`; isolated root/child/grandchild to host task by ID/title/parent, same project and cross-project when privacy permits. executable delivery denied; safe attributed reports available without entering a host turn. Include automatic subtask reports and waiting replies. Benign same-boundary task messaging/delegation remains a positive control.
- **Mixed/forged/persistent manager turns:** worker text with fake owner headers/approval JSON, human host pick plus worker input in both orders, FYI stored without wake then retrieved in history/recap, previous malicious turn plus later human pick, Captain → Coordinator → another Captain, reply/wait tool results. Script one forbidden host action in each actual turn seam and assert MCP denial. This tests call routing, not model obedience.
- **Hooks:** directly seed an enabled hook through HookEngine. An isolated task in a now-host-default project fires create_task with inert adversarial summary/title substitutions. New root must be contained or fire must fail without a task; manager ceiling cannot repair this direct HookEngine → TaskManager route. Deny host executable send actions too; message/report actions remain allowed data. Keep loop/dedup/privacy behavior. Manager create/update/enable hook attempts are always denied under the proposed ceiling.
- **Schedules:** manager create/update/run schedule denied even with a contained-looking prompt if schedules are outside its allowlist. Independently seed schedules through Scheduler; a later default change or worker-substituted payload cannot widen the approved execution boundary. Existing human automation can still perform its specifically authorized behavior through its own path.
- **Retries/resume:** retry the same denied request on the same MCP client and a freshly rebuilt server/client; include Captain interrupted-turn watermark rewind, missing-session recap, summary/compact and harness continuation. No previous turn pick/session state changes the ceiling. Fake CLI runners preserve/report resume state without executing commands. Restore worker/hook boundary state from the temp Store and reassert unchanged containment.

Run the manager turn integration for Coordinator/Captain × Claude/Codex × first/resumed session. Task event matrix is Claude/Codex/Cursor; Cursor is not a manager harness (`shared/agentCli.ts:15`). Cover one representative forbidden call across the full turn matrix and the full operation inventory at the MCP layer; avoid multiplying every operation by every turn/harness/scenario.

## External manager connector regressions

Current manager connector acquisition occurs before each run: `server/captains.ts:696-703,1517-1520` and `server/orchestrator.ts:242-249,959-962`. Claude launch writes the MCP config and merges connector env (`captains.ts:1504-1514`, `orchestrator.ts:947-956`). The service resolves credentials/refreshes tokens in `server/connectors/service.ts:66-83`. These are distinct enforcement seams.

1. Seed enabled fake HTTP and stdio connectors scoped to both manager roles. Manager session selection returns `NO_SESSION_CONNECTORS` before any credential/refresh/probe method is called. Fake fetch and command callbacks must remain untouched. Test Coordinator and Captain, including a project with its own identity and connector scope. Merely removing allowedTools is insufficient if config/env/refresh still receives them.
2. Both harness launch builders on first/resumed turn/summary/compact receive only the Box Yard endpoint, no external config or connector env markers. Include a prior config containing an inert external entry; resumed launch rewrites/ignores it. Keep shell/approval/strict-MCP restrictions. Use fake credentials in the temp data directory; never read a real CLI login/home.
3. A configured connector falsely advertised as read-only is still absent from managers. A manager asking another manager to use it cannot restore it. Task connector positive controls remain scoped to their existing allowed runner/project and containment policy; these are not a manager bypass.
